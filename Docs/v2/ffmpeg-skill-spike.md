## Contract capture and semantics

The pinned source's documented generator was run directly as `python scripts/_contract.py --json`; `python scripts/_contract.py doctor --json` captured dynamic host capability detection. This uses the upstream contract mechanism, not a hand-written reconstruction. The output contains 42 tools and the full input/output schemas in [contract.json](research/ffmpeg-skill-v1.26.0/contract.json); the local capability report is [doctor.json](research/ffmpeg-skill-v1.26.0/doctor.json). Their sizes, SHA-256 hashes, tag, commit, and version are recorded in [provenance.json](research/ffmpeg-skill-v1.26.0/provenance.json).

The structured input schemas are generated from each script's `argparse` parser and set `additionalProperties: false`. Each tool lists required fields, positional fields, types, enums, defaults, and constraints. Examples of exact input/result surfaces from the captured contract:

| Tool | Required and representative typed inputs | Result fields and verification |
|---|---|---|
| `probe` | `inputs[]`; optional `analyze`, `compact`, `field`, `timeout` | `file`, `format`, `size_bytes`, `duration`, `video`, `audio`, stream and tag metadata; it is itself read-only verification. |
| `look` | `input`; optional `at[]`, `tiles`, `width`, `no_timecode`, `output` | `status`, `output(s)`, `probe`, `verification`, `verified`; a written sheet is probed. |
| `scenes` | `input`; optional `threshold`, `shots`, `speech`, `audio_peaks`, `beats`, `highlights`, `sheet`, `edl` | scene ranges/count, shot labels and flow proxy, speech ratio, audio peaks, optional output; analysis result needs no follow-up tool. |
| `cropdetect` | `input`; optional `motion_centre`, `samples`, `seconds`, `limit` | measured crop and motion-centre values; analysis only. |
| `silence` | `input`; `list`, threshold, minimum silence/keep durations, or edit options | silence ranges, keep ranges, removed duration, optional output; a written edit is followed by `probe`. |
| `loudness` | `input`; `measure_only`, target `lufs`, `tp`, optional output | measured input/result/targets and optional output; written output is followed by `probe` and `check`. |
| `check` | `input`; optional platform, aspect, max duration/size, LUFS/true-peak limits, `no_loudness` | `checks`, `failed`, `warnings`, `ok`; read-only verification. |
| `cut` | `input`; start/end or segments, `accurate`, tolerance/snap settings, output | precision, expected duration, duration error, re-encode mode, output probe and `verified`; written output is followed by `probe`. |
| `fit` / `crop` / `speedramp` | `input`; typed aspect/fit or numeric crop rectangle, or required typed speed segments | new media output and probe; visual edits require `look`, while speedramp requires probe plus look. |
| `overlay` / `graphics` / `caption` | `input` plus typed text/image/template/subtitle/font/style/timing fields | output/probe/verification; picture changes require `look`. No caller-supplied filtergraph is in these structured schemas. |
| `audio` / `export` | audio: typed gain, mix, dynamics, and codec options; export: named preset and output | output probe; audio may need `check`, export requires `probe` and `check`. |

The complete snapshot is authoritative for every field, including conditional FFmpeg capabilities and output schemas. Success is `status: completed` with exit 0; writes count as successful only when the output is non-empty and ffprobe reads a stream. Failure JSON has `status: failed`, `exit_code`, and `error.kind/message` (with some tools adding `code` and `retryable`). The contract's error kinds are `input`, `ffmpeg`, `output`, `missing_tool`, `timeout`, `verification`, and `interrupted`. Missing FFmpeg/ffprobe is 127, timeout 124, interruption 130/143, and ordinary execution/verification failures 1; `doctor` uses 0/1/2 for okay/missing/unknown.

`--dry-run` is not equivalent to “does no work” for every tool. Editing tools such as cut, fit, and export plan without writing media. `probe` and `check` still do their reads; scenes, cropdetect, silence, and loudness still execute their measurements while skipping files such as sheets, EDLs, or normalized output. `verify` advertises no supported dry-run and executes its steps. The generated dry-run command strings are evidence for a human/internal adapter only and must never be returned to a model.

`--json-brief` replaces command strings with a count on **success**, but failures retain the full failure document and its command field. Tool JSON therefore cannot be forwarded wholesale on either success or failure. v1.26 also deprecates several success fields in favor of `result_v2` for the next major; a future adapter needs an explicit response-version policy even though this release still reports contract version 1.0.

## Adversarial and boundary review

### Shell, argv, filters, and agent-facing output

The pinned contract says shell use, network access, arbitrary executables, and input mutation are false. The code builds subprocess argument lists with `shell=False` and resolves only the named Python script plus `ffmpeg`/`ffprobe` from `PATH`. The structured tool schemas expose typed media fields, not a raw FFmpeg filtergraph. This removes shell-string injection from the normal typed CLI path, but it is not an authorization boundary: text, subtitle, LUT, logo, input, and output paths are still caller-controlled data.

The upstream MCP server and its contract also retain a **non-canonical `argv: string[]` compatibility branch**. It bypasses the structured argument mapping and passes a raw CLI list to the named tool script. The tools also return `commands` strings, and `--plan` persists an argv list and those commands. Replex must reject the `argv` key, not register candidate MCP tools for the model, not expose command-bearing result JSON, and not accept candidate plan files as model output. `--json-brief` is insufficient as a sanitizer because its failure response is intentionally untrimmed.

### Paths, input preservation, outputs, and cleanup

The tools accept arbitrary local filesystem paths and may default outputs beside their input. There is no Replex-project/job-root containment in this skill. Its shared guard resolves paths with `realpath` to reject output equal to input (including the ordinary symlink-to-same-file case); the multi-segment cut path has an additional explicit check. That guard is not a job-root sandbox, does not establish an authorized asset handle, and is not a defense against a path changing between check and use. Hard-link identity was not checked. The optional runtime symlink test was not completed: the local shell safety layer rejected the combined create/test/cleanup command before it ran; the behavior conclusion is source-reviewed only.

Source review found failure cleanup for newly created/changed FFmpeg outputs and sibling-temp staging before replacing an existing output. The tiny actual cut also preserved the source hash. Neither finding makes arbitrary outputs safe for Replex: always pass an adapter-generated output under a private per-job staging directory, resolve and check paths at execution time, keep imported inputs read-only, verify/hash the completed artifact, then atomically register it in Replex-owned state.

### Plans, stale input, JSON, and unsupported features

`--plan` writes `tool`, `cwd`, `argv`, command strings, output, verification steps, and input fingerprints. `render.py` checks the fingerprint then executes the saved argv through the named script. The fingerprint is file size plus SHA-256 of the first and last 8 MiB; a same-size middle-only edit to a file larger than 16 MiB is a static-review false-negative. Plan mode was not run and should be excluded from the proposed subset; Replex's frozen `MediaExecutionJob` must remain the only plan.

I injected malformed ffprobe JSON (`{`) into the pinned probe parser on the synthetic file. It returned exit 1 with `status: failed`, `error.kind: ffmpeg`, `error.code: FFMPEG_EXECUTION_FAILED`, and `retryable: false`; it did not report a false success. Separately, the MCP wrapper treats a zero-exit child with malformed JSON as plain text instead of a schema error. Any future adapter must strictly parse one JSON document, reject malformed/unknown shapes, and map only known error kinds; MCP was not run.

Timeouts default to 1,800 s per FFmpeg operation (`FFMPEG_SKILL_TIMEOUT`; zero disables), ffprobe calls use a 120 s ceiling, and doctor capability probes use short 10 s ceilings. Nested script dispatch adds an outer `4 × timeout + 60 s` ceiling. The source tracks and terminates direct child processes and removes their partial outputs, but no process-group or Windows job-object tree kill was found. Its Windows source comment states SIGTERM is not delivered there; Ctrl-C is handled. Process-tree timeout/cancel and partial cleanup under an interrupted real encode were not exercised. Treat the documented timeout as a direct-process behavior, not proof of Replex cancellation semantics; the adapter would need its own process-tree owner, deadline, and idempotent cancellation test.

The local `doctor` result is a concrete unsupported-feature finding: this Windows build advertises drawtext yet crashes when rendering it, leaving `graphics` unusable. `look` succeeded with `--no-timecode`; that workaround does not generalize to text graphics. No Linux/macOS runtime claim is made. Use `doctor --json` for conditional capabilities on each selected worker image and reject missing/unknown requirements before starting a job.

## Proposed constrained subset

If a later V2-401 adapter is authorized after the native V2 baseline/parity gate, evaluate only these non-editing capabilities first:

1. `probe` for technical metadata.
2. `look` for bounded contact sheets, with timecode disabled on hosts whose drawtext probe fails.
3. `scenes` for measured scenes, shot-flow proxy labels, speech-energy ratios, and audio peaks; treat all as advisory evidence.
4. `silence --list` and `loudness --measure-only` for measurement only; neither may create canonical edits or set final delivery acceptance.
5. `check` as an additional diagnostic whose individual rows are mapped into Replex-owned verification requirements.

`cropdetect --motion-centre`, waveform output, every mutating edit, export, candidate plan/render, batch, and MCP remain outside this proposed subset. A future adapter must accept only frozen Replex jobs and authorized handles, stage output beneath a private job root, expose neither `argv` nor `commands` to any model-facing path, validate the exact pinned contract/capabilities, strictly parse results, verify hashes/streams/duration, own process-tree deadline/cancel semantics, and keep the native backend selectable.

## Supply chain and rollback

The candidate source is MIT and its current Python runtime uses the standard library; Node is only for installation. This spike did not install the npm package, vendor source, or add a dependency. The tag and full commit are pinned in the evidence, but tag-signature verification, npm tarball integrity/source equivalence, and a vulnerability/dependency audit were not performed. Before distribution, preserve the MIT notice and verify the published artifact against its source.

The locally measured Gyan FFmpeg reports `--enable-gpl --enable-version3`, including GPL-enabled codecs such as libx264. This is a separate licensing question from the skill's MIT license; no FFmpeg binary was copied into Replex. FFmpeg's [official legal page](https://ffmpeg.org/legal.html) explains that optional GPL components change FFmpeg's licensing obligations. Review the exact FFmpeg build and codec distribution plan before shipping any binary or linking libraries.

Rollback is a revert of this research-only commit and removal of its evidence directory. No runtime selection or canonical state needs migration. If an adapter is separately approved later, keep the native backend selectable and register no partial output until Replex verification passes, consistent with ADR-004.
